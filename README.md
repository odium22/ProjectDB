# ProtectDB

Учебный проект по предмету **«Разработка, администрирование и защита баз данных»**.
Тема: **проектирование схемы БД и прикладная логика** для системы учёта доступа и
аудита.

Сейчас реализованы схема БД и слой логики. UI (WPF) и фронтенд (React через API)
подключаются позже поверх готовых сервисов.

## Идея

1. Проектируем БД (сущности, связи, ограничения) — **сделано**.
2. Привязываем индивидуальное приложение (консоль → далее WPF) — **драйвер готов**.
3. Привязываем сервис `API + React`, где фронт просто выводит данные — **в планах**.

## Стек

- .NET 10 / C#
- Entity Framework Core 10 + SQLite
- Миграции EF Core
- xUnit (тесты логики)

## Архитектура

Решение разделено на слои, зависимости идут строго «сверху вниз»:

```
ProtectDB.Console  ─┐
ProtectDB.Tests    ─┼─►  ProtectDB.Application  ─►  ProtectDB.Data  ─►  ProtectDB.Domain
```

| Проект                    | Назначение                                                        |
|---------------------------|-------------------------------------------------------------------|
| `ProtectDB.Domain`        | Модель предметной области: сущности, перечисления, константы.     |
| `ProtectDB.Data`          | EF Core: контекст, конфигурации таблиц, миграции, регистрация DI. |
| `ProtectDB.Application`   | Логика: сервисы пользователей, ролей, доступа, аутентификации, аудита. |
| `ProtectDB.Console`       | Временная точка входа (позже заменяется на UI/API).               |
| `ProtectDB.Tests`         | Тесты прикладной логики.                                          |

Ключевые принципы:

- домен не зависит ни от чего;
- доступ к данным изолирован в `Data`;
- UI/API работает только с сервисами приложения, а не с БД напрямую;
- интерфейсы сервисов вынесены в `ProtectDB.Application/Abstractions`.

## Модель данных

Подробное описание — в [docs/database-schema.md](docs/database-schema.md).

Основные таблицы: `Users`, `Roles`, `Permissions`, `Resources`,
`UserRoles`, `RolePermissions`, `Sessions`, `AuditEntries`.

Модель реализует **RBAC** (роль → права) и **журнал аудита** всех действий.

## Запуск

Требуется .NET 10 SDK.

```powershell
# восстановить локальный инструмент dotnet-ef
dotnet tool restore

# сборка
dotnet build

# интерактивная консоль администратора
dotnet run --project src/ProtectDB.Console

# сценарный прогон без ввода (демонстрация логики)
dotnet run --project src/ProtectDB.Console -- --demo
```

Учётная запись по умолчанию (создаётся при первом запуске):

- логин: `admin`
- пароль: `Admin#12345`

> Пароль по умолчанию предназначен только для учебного запуска.

## Миграции

```powershell
# создать новую миграцию
dotnet ef migrations add <Имя> --project src/ProtectDB.Data --startup-project src/ProtectDB.Data

# применить миграции к БД
dotnet ef database update --project src/ProtectDB.Data --startup-project src/ProtectDB.Data
```

Строка подключения задаётся в `src/ProtectDB.Console/appsettings.json`
(по умолчанию `Data Source=protectdb.db`).

## Тесты

```powershell
dotnet test
```

## Что демонстрирует проект (администрирование и защита)

- хранение паролей как PBKDF2-хэш (SHA-256) со случайной солью и 100 000 итераций;
- сравнение хэшей за постоянное время (защита от атак по времени отклика);
- блокировка учётной записи после 5 неудачных входов;
- разграничение доступа через роли и права;
- сессии входа с ограниченным сроком жизни и отзывом;
- полный журнал аудита: кто, что, когда и с каким результатом сделал.
